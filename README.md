# Склад + Учёт времени — объединённый портал

Один сайт, один домен, один порт. «Склад» отдаётся из корня, «Учёт времени» —
из `/time`. Оба приложения по-прежнему хранят свои данные отдельно (склад —
SQLite, учёт времени — `data.json`), но **учётная запись одна**: логин и
пароль задаются один раз в «Складе», а «Учёт времени» узнаёт, кто вы, по той
же cookie сессии (ставится с `Path=/`, поэтому видна везде на домене).

```
merged/
  storage/       — «Адресное хранение склада», источник учётных записей, живёт в /
  timetracker/   — «Учёт рабочего времени», доверяет сессии склада, живёт в /time
  gateway/       — единственная точка входа: монтирует оба приложения в одном
                    Express-процессе на одном порту (см. gateway/server.js)
```

## Запуск

```bash
cd storage      && npm install
cd ../timetracker && npm install
cd ../gateway     && npm install

PORT=8080 npm start   # из папки gateway
```

Готово — весь портал на одном порту:
- Склад: `http://ваш-домен:8080/`
- Учёт времени: `http://ваш-домен:8080/time/`

Вход только один — в «Складе» (`/`); кнопка «⏱ Учёт времени» в шапке ведёт на
`/time/`, сессия уже действует.

### Как это работает технически

`gateway/server.js` не переписывает оба сервера в один файл, а монтирует их
как готовые Express-приложения:

```js
app.use('/time', require('../timetracker/server'));  // сначала более точный путь
app.use('/', require('../storage/server'));           // потом корень (у него есть catch-all)
```

Для этого:
- `storage/server.js` и `timetracker/server.js` теперь экспортируют `app`
  (`module.exports = app`) и вызывают `app.listen(...)` только если их
  запустили напрямую (`node server.js`), а не через `require()`.
- Все абсолютные пути во фронтенде `timetracker/public/*` (`href="/..."`,
  `fetch('/api/...')`, `manifest.json`, `sw.js`) переписаны с префиксом
  `/time`, поскольку теперь это приложение живёт не в корне порта, а под
  `/time` того же домена.
- `PORTAL_URL` для «Учёта времени» гейтвей по умолчанию выставляет в `/` —
  так кнопка "← Портал" в учёте времени ведёт на корень домена, а не на
  отдельный хост/порт.

### По-прежнему можно запускать по-старому (два порта)

Если нужен старый режим (два отдельных процесса на двух портах — например,
для раздельного масштабирования), `storage/server.js` и
`timetracker/server.js` всё ещё прекрасно работают самостоятельно:

```bash
cd storage && PORT=3000 npm start
cd timetracker && PORT=3001 STORAGE_DIR=../storage npm start
```

В этом случае в `storage/public/index.html` раскомментируйте
`window.__TIMETRACKER_PORT = 3001;`, чтобы кнопка в шапке снова строила
ссылку на отдельный порт вместо `/time/`.

Переменные окружения `timetracker` (актуальны в обоих режимах):
- `STORAGE_DIR` — путь до папки `storage` (по умолчанию соседняя папка)
- `STORAGE_PORT` — порт склада для двухпортового режима (по умолчанию 3000)
- `PORTAL_URL` — явный адрес портала; гейтвей выставляет его сам в `/`

## Как это устроено

1. **Вход только один — в «Складе».** У «Учёта времени» больше нет своих
   логина/пароля: он читает ту же cookie `wh_session` и проверяет её прямо по
   базе склада (`storage/db.js`, `storage/auth.js` — эти два модуля
   импортируются из `timetracker/server.js` как есть, без копирования).
2. **Базы не пересекаются.** В `storage` — товары, ячейки, задания, чаты. В
   `timetracker/data.json` — отметки прихода/ухода, графики смен, табель.
   Из общей базы склада учёт времени берёт только identity (логин/пароль/сессия) —
   ничего больше не читает и не пишет.
3. **Кто есть кто в учёте времени.** Локально в `data.json` у каждого
   профиля (admin/guard/employee) есть поле `login` — это username из
   общей базы склада, а не собственный логин. Привязка делается один раз
   через `/admin.html`: сначала заводите аккаунт в «Складе» (раздел
   «Аккаунты»), потом на странице сотрудников учёта времени указываете этот
   же логин.
4. **Первый администратор** учёта времени назначается автоматически: как
   только человек с правом «управлять пользователями» на складе первый раз
   откроет учёт времени, он становится там админом (дальше уже сам
   привязывает охрану и сотрудников).
5. **Выход разлогинивает сразу оба сайта** — кнопка «Выйти» в учёте времени
   удаляет ту же сессию, которой пользуется склад.
6. **Меню.** В шапке склада (и в нижней панели на телефоне) появилась кнопка
   «⏱ Учёт времени», которая просто открывает второй сайт — сессия уже
   действует, повторного входа не будет.

## Что стоит доделать при желании
- Полноценный UI для назначения роли (admin/guard/employee) при привязке —
  сейчас поддержано на бэкенде (`POST /api/employees` принимает `role`), но
  форма в `admin.html` пока создаёт только `employee`; для охраны/доп.
  администраторов можно дернуть тот же эндпоинт с `role: "guard"` вручную
  или доработать форму.
- Для продакшена перед гейтвеем стоит поставить nginx/Caddy с HTTPS
  (`app.set('trust proxy', 1)` в `storage/server.js` уже рассчитан ровно на
  один такой хоп впереди) и запускать сам гейтвей через pm2/systemd.
